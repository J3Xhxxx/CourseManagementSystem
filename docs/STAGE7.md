# 第七阶段：方案评价、偏好排序与 Top-K（v0.9）

本轮实现任务书第四阶段的“个性化方案评价、Top-K 维护”：只对**合法**方案做评价，按用户设置的偏好优先级排序，并用固定容量大根堆只保留较优的前 K 个，不再把全部合法方案同时留在内存里。

本轮不改变硬约束语义：必选课程、学校固定课程、个人锁定教学班和禁止时间仍决定方案是否合法，软偏好只决定合法方案之间的顺序。

## 二、六项评价指标

评价只使用方案自身保存的时间位集合，**逐周**扫描真实周次，不把整个学期叠加成一张课表：否则“第 3 周周一有课”和“第 5 周周一有课”会被误并成一天。

设学期 W 周、每天 7 天、每天 6 个大节：

| 指标 | 定义 | 方向 |
| --- | --- | --- |
| earlyMorningCount 早课次数 | 第一大节（早八）有课的“周次 × 星期”数量；同一天同一周只计一次 | 越小越好 |
| classDays 上课天数 | 有课的“周次 × 星期”去重数量；同一周不同两天算两天 | 越小越好 |
| totalGapPeriods 空堂节数 | 同一天内第一节课到最后一节课之间没有课的大节数之和 | 越小越好 |
| maximumContinuousPeriods 最大连续节数 | 单日连续有课的最长节数，跨周比较取最大值 | 越小越好 |
| latestEndPeriod 最晚结束节次 | 全学期所有有课日中最晚结束的节次，没有课为 0 | 越小越好 |
| freeHalfDays 空闲半天数 | 完全没课的半天数：上午 1-3 节、下午 4-6 节；上限 W×7×2 | 越大越好 |

指标方向由指标本身固定，用户只调整优先级顺序，不能把“空堂越少越好”改成“空堂越多越好”。

口径说明（报告里需要写清，避免评审追问）：

- 上课天数是“全学期有课的天数”，不是“每周平均上课天数”。默认 20 周时最大可达 140（20×7）。
- 空堂只统计“第一节课和最后一节课之间”的空缺，不把当天最早课之前、最晚课之后的时间算成空堂。
- 空闲半天数是整学期的半天数（20 周时为 280 个半天单位），不是“一周里有几个空闲半天”。

### 手工算例

一个教学班：第 1 周周一第 1 节 + 第 2 周周二第 2-3 节（每学期 20 周）：

| 指标 | 值 | 说明 |
| --- | ---: | --- |
| 早课次数 | 1 | 只有第 1 周周一第一大节 |
| 上课天数 | 2 | (1,周一)、(2,周二) |
| 空堂节数 | 0 | 两天都没有夹在中间的空缺 |
| 最大连续节数 | 2 | 周二第 2-3 节 |
| 最晚结束节次 | 3 | 周二第 3 节 |
| 空闲半天数 | 278 | 280 − 2（被占用的两个半天） |

另一个教学班：第 1 周周一第 1 节和第 3 节：空堂 1 节、最大连续 1 节、最晚第 3 节、空闲半天 279。

## 三、偏好优先级与排序

`PreferenceOrder` 保存六项指标的一个排列，必须恰好包含六项且不重复（读取 JSON 或界面写回时校验，非法顺序直接报错）。

排序是**字典序**：先比较优先级最高的指标，只有它相等时才比较下一项。默认顺序为：

```text
早课次数 优于 上课天数 优于 空堂节数 优于 最大连续节数 优于 最晚结束节次 优于 空闲半天数
```

六项指标全部相同的两个方案，再按教学班 ID 序列比较，保证同一份输入每次运行的顺序完全一致（可重复）。

复杂度：单次比较 O(6)；给 n 个方案排序为 O(n log n) 次比较。评价一个方案需要扫描 O(W × 7 × 6) 个时间位，即与学期规模成正比、与方案内教学班数无关。

## 四、Top-K 大根堆

`BoundedMaxHeap<T, HeapAbove>` 是一个固定容量的二叉堆，比较器 `heapAbove(a, b)` 表示 a 应排在 b 上面（**a 比 b 更差**），因此：

- 堆顶始终是“当前保留元素里最差的一个”；
- 堆未满时直接插入并上浮；
- 堆已满时，新元素优于堆顶就替换堆顶并下沉，否则直接丢弃；
- 取出时（`drainSorted`）逐个弹出堆顶并反向填充，得到从优到差的完整顺序。

这样内存占用固定为 O(K)，不需要保存全部合法方案。`ScheduleAbove` 把 `ScheduleRanking::worse` 作为 `heapAbove`，即“更差的方案在堆顶”。

搜索语义随之变化：

- 方案数上限不再中止搜索：装满 K 个后继续搜索，更好的方案会替换掉当前最差的一个，因此**搜索跑完时保留的就是全局最优的前 K 个**；
- `SearchResult::totalSolutions` 记录搜索中遇到的全部完整合法方案数；
- `SearchStatus::Complete` 表示搜索树全部走完且方案数不超过 K（全部方案都在结果里）；
- `SearchStatus::SolutionLimit` 表示搜索树全部走完但合法方案多于 K（只保留较优的前 K 个）；
- `NodeLimit`、`Cancelled` 表示搜索未完成，此时保留的只是已探索部分中较优的方案，界面明确说明“不能视为全局最优”；
- `SearchResult::complete()` 对前两种状态返回 true，对后两种返回 false。

## 五、独立复核

`ScheduleValidator` 现在除了检查课程、锁定、固定课程、禁止时间和两两冲突，还会用 `ScheduleEvaluator` **独立重算**六项指标，与方案保存的指标比较，不一致时报 `ValidationCode::MetricsMismatch`。这样“Generator 算出的评价”与“独立算法算出的评价”互为对照，也能发现展示过期指标的情况。

因为校验器会复核指标，任何构造方案的地方都必须先评价再校验（`BruteForceGenerator` 已按此顺序）。

## 六、本轮实际验证

用 g++（-Wall -Wextra -Wpedantic -Wconversion）直接编译构建不依赖 Qt 的核心部分，并运行临时检查程序，覆盖：

| 用例 | 结果 |
| --- | --- |
| 手工指标算例（两次课跨两天） | 早课 1、天数 2、空堂 0、最长连续 2、最晚第 3 节、空闲半天 278 ✅ |
| 空堂算例（周一第 1、3 节） | 早课 1、天数 1、空堂 1、最长连续 1、空闲半天 279 ✅ |
| 大根堆不变量（保留最大/最小 1、3 个，容量大于元素数） | 每次插入后与暴力求前 K 完全一致 ✅ |
| 偏好优先级改变最优解 | 早课优先选早课 0 次的方案；上课天数优先选 18 天的方案 ✅ |
| Top-K 与暴力枚举对照（27 个方案保留 5 个） | 保留的 5 个与暴力枚举全局前 5 完全一致，内部有序，逐个通过校验 ✅ |
| 尝试上限 | 报告 NodeLimit 且声明不能视为全局最优 ✅ |
| 方案数少于 K | 报告 Complete，全部方案保留 ✅ |
| 指标被篡改 | 独立校验器报出 MetricsMismatch ✅ |

本轮修掉的两个实现缺陷（记录在案，避免以后重犯）：

1. `freeHalfDays` 最初按“跨周去重的星期 × 半天”统计，实际应为整学期的半天单位数；
2. 大根堆的下沉比较方向写反，且替换分支缺少提前返回，导致堆可能丢掉真正更优的方案——用“插入后与暴力前 K 对照”的不变量测试才发现。

## 七、后续可做

1. 无解诊断增强：逐项临时放宽禁止时间、锁定或必选课程并重搜，报告“解除某项限制后可恢复的合法方案数”，并明确声明不是最小修改方案。
2. 冲突图增量更新：目前增删改教学班仍全量重建 O(n²) 冲突边，可以只重算受影响的顶点。
3. 可选拓展“最小改动换课”：以既有课表为基准，增加 `changedCourseCount` 指标参与排序。
4. 单日最多/最少课程量指标：任务书列出的评价维度之一，本轮按约定只实现 BRIEF 第六节的六项。
