# 第五轮：必选课程、锁定教学班与禁止时间

v0.5 将三类硬约束接入数据模型、生成器、独立验证器、JSON 项目和界面。约束决定哪些方案合法；当前结果仍按搜索发现顺序展示，不做软偏好排序。

## 使用规则

| 设置 | 含义与边界 |
| --- | --- |
| 必选课程 | 精确的参与集合：每门恰选一个教学班，集合之外的课程不参与。本轮没有“未勾选课程可任选”的语义 |
| 锁定教学班 | 指定必选课程必须选择的一个班，选择后包含该班全部 Meeting；同一课程最多锁定一个班 |
| 禁止时间 | 明确到周次、星期、节次的时间点集合；教学班任一 Meeting 碰到任一点，该班就不能入选 |

新增课程默认必选。界面锁定一个班会自动勾选所属课程，改锁同课程另一个班会替换旧锁定；取消必选会同时解除锁定，单独选择“不锁定”则保留必选状态。

显式空必选集合产生一个零课程、零上课时段的空方案，禁止时间仍可保留。未勾选的课程即使没有教学班，也不阻止其他课程生成。必选课程没有教学班则无解，并返回该课程名称。

时间上矛盾的约束可以设置和保存，例如两个锁定班时间重叠、锁定班落入禁止时间。配置结构合法不代表存在可行方案；搜索负责说明无解原因。

| 类 | 本轮职责 |
| --- | --- |
| UserConstraints | 保存 requiredCourseIds、lockedTeachingClassIds、forbiddenTimes；校验学期一致、引用存在、锁定课程已必选、同课程至多一个锁定 |
| CourseService | 持有唯一项目约束，通过 setConstraints 校验并提交；数据增删改时事务式维护约束引用 |
| ScheduleGenerator | 仅为必选课程建立候选列表，应用锁定与禁止时间过滤；预检查直接锁定冲突，再执行基础 DFS |
| ScheduleValidator | 独立从 Meeting 展开坐标，验证精确课程覆盖、锁定班、禁止时间、教学班互斥、时间冲突及结果位图一致性 |
| BruteForceGenerator | 枚举必选课程原始教学班的完整笛卡尔积，再使用独立验证器筛选；不复用生成器的候选过滤 |
| JsonProjectStore | 保存约束，严格读取、引用验证；保留原子写入；当前格式见 DATA_FORMAT.md |
| ProjectController | 提交约束，设置修改标记并发出 dataChanged；设置未变化时不清空结果 |
| ConstraintPanel | 必选勾选、锁定下拉框、周次/单双周/星期/节次输入及禁止时间列表 |
| CandidatePanel | 展示候选、搜索状态，以及没有教学班、没有剩余候选、锁定时间冲突的解释 |
| TimetableWidget | 按当前周显示禁止时间；单班预览标出与禁止时间的重叠 |

SearchController 沿用上一轮项目快照和后台线程设计。约束通过项目快照一起进入搜索，修改约束会取消旧搜索并丢弃过期结果；保存项目不会使当前方案失效。

## 一致性与编辑

CourseService 对外返回只读约束。调用方复制约束、修改副本，再调用 setConstraints；失败时项目及原约束保持不变。核心接口不自动修复非法锁定，界面负责在勾选或锁定操作中同时提交相应的课程选择。

- 课程代码或名称变化时，必选 ID 和所属锁定班 ID 一起改写；未必选课程改名后仍不必选。
- 教师变化时，教学班 ID 变化，锁定跟随新 ID；时间、教室变化也不会取消该班锁定。
- 删除教学班清除其锁定，但不取消所属课程的必选状态。
- 删除课程清除其必选 ID 和所属教学班锁定；禁止时间保留。
- CSV 合并保留已有课程的必选状态、锁定和禁止时间，新增课程默认必选；非法整批数据仍整体回滚。

时间索引保持不变：

```text
index = (week - 1) * 7 * 6 + (weekday - 1) * 6 + (period - 1)
```

禁止时间和课程时间采用相同学期长度的 TimeBitSet。方案的 occupiedTimeBitmap 只记录真实上课时间，不包含禁止时间；禁止时间单独用于合法性判断和显示。

## 搜索与无解说明

生成器保持项目中的课程、教学班顺序。只处理 requiredCourseIds 内的课程；存在锁定时，该课程仅保留锁定班；随后排除与禁止时间相交的教学班。缺少教学班和过滤后候选为空分别记录，避免把“没有录入”混同于“被设置排除”。

搜索前检查锁定班两两交集，以及每个锁定班与禁止时间的交集，返回具体班 ID 和全部重叠 TimeSlot。界面显示课程、教师，以及按星期/节次整理的实际周次。没有上述直接原因但完整搜索无解时，提示剩余教学班不能相互兼容，不声称已找到最小无解原因。

候选过滤后仍使用基础 DFS、位图冲突剪枝和独立叶子验证。最多方案数、最多尝试次数、取消、额外探测一个合法叶子等上限语义沿用 [第四轮说明](STAGE4.md)。节点统计只计算过滤后实际尝试的教学班，不把被前置约束排除的班计为 DFS 尝试。

独立枚举基线保留各必选课程的原始教学班选择，直到完整组合形成后才验证锁定及禁止时间，因此能发现生成器候选过滤过多或过少的问题。其 maxCombinations 限制也针对未过滤的原始笛卡尔积，只适合小规模对照。

## 界面与文件

右侧新增“选课约束”页签，工具栏可直接打开。设置立即生效并标记项目已修改。禁止时间支持：

1. 输入显式周次或范围，例如 `[1-5,7-9周]`，并按单周或双周过滤。
2. 选择周一至周日、第一至第六节的闭区间，添加整个范围。
3. 按输入范围解除禁止，或删除表格中按“星期＋节次”合并的一行。
4. 双击已有行，将该行周次及节次载入表单，便于解除其中一部分。

重复添加是集合并集。非法输入不改变已有设置。课表只标红当前周真实存在的禁止时间；其他周的禁止不会影响本周。选中与禁止时间重叠的单班时，会保留教室信息并标明冲突。

本阶段当时使用 version 3 的 teachingClasses 和 constraints，空必选集合可以不选任何课程；缺失字段、未知字段、重复 ID/禁止时间点、越界或非整数坐标、悬空约束引用均拒绝。2026-10-07 已改为 version 4，必选集合必须包含学校固定课程，不保留开发期旧格式兼容；2026-10-15 升为 version 5，约束中增加六项指标的 `preferences` 顺序。当前格式见 [DATA_FORMAT.md](DATA_FORMAT.md)。

方案仍是临时结果，不写入 JSON；重新打开项目后需再次生成。课程或约束变化会取消正在进行的搜索并清除方案，保存和没有实际改变设置的操作保留方案。
